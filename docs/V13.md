# Lotofácil Astro v13 — Observatório

Evolução do v12. O objetivo continua o mesmo: **encontrar sinais no mapa que
ajudem a acertar mais que 9**. O que muda é que o v13 foi construído para
não conseguir se enganar: se um sinal existir, ele aparece; se não existir,
o sistema mostra isso em vez de exibir acertos ilusórios.

## Como usar

1. Cole `dist/lotofacil-astro-v13.jsx` como artifact no Claude (mesmo formato do v12).
2. **Histórico → Importar mapas em lote**: cole os mapas em inglês, cada um com uma linha de cabeçalho
   (`#3650`, `Concurso 3650` ou `3650:`), confira e importe. Mapas com erro aparecem marcados e não entram no motor.
3. **Concurso**: cole o mapa do próximo sorteio, "Gerar previsão" e "Registrar jogos no diário".
4. Depois do sorteio: **Histórico → Adicionar resultado**. O diário apura sozinho.
5. **Sinais**: rode a descoberta; pré-registre o que parecer forte.
6. **Placar**: veja o desempenho honesto e rode o teste de permutação.

Os dados ficam numa chave nova (`lotofacil-astro-v13`); o v13 começa só com
os 321 resultados oficiais, sem mapas e sem os jogos antigos do v12.

## Formato do mapa (inglês)

Exatamente o do site, linha a linha. Veja `test/fixtures/mapa-modelo.txt`.

```
Sun in Aries 23°59’, in 6th House
North Node in Pisces 6°43’, Retrograde, in 4th House
ASC in Scorpio 27°21’
1st House in Scorpio 27°21’
Sun Octile Moon (Orb: 1°32’, Applying)
Mars: 0°46’36’’ (Fast, cca 1.48x avg speed)
```

O parser confere tudo pela geometria:
- a casa de cada ponto é recalculada a partir das cúspides (se o texto diverge, avisa e usa a geometria);
- o orbe de cada aspecto é conferido contra as posições (se não bate, o aspecto é descartado e avisado);
- **nenhuma linha some em silêncio**: o que não for reconhecido vira aviso.

## Sinais extraídos (o que o mapa "diz")

Nenhum sinal traz número pré-definido: a ligação sinal → número é sempre aprendida dos dados.

| Grupo | Exemplos |
|---|---|
| Casa | planeta na casa N; angular/sucedente/cadente; regra dos 5° (migrando); stellium; grupos na mesma casa |
| Signo / Grau | signo e elemento; grau exato; 0°; anarético (28–29°); Via Combusta |
| Dignidade | domicílio, exaltação, peregrino, exílio, queda; alegria planetária |
| Condição solar | cazimi, combusto, sob os raios |
| Velocidade | rápido / médio / lento / estacionário / retrógrado (usa as velocidades do texto) |
| Lua | fora de curso (calculada pelas velocidades); próximo e último aspecto; natureza (benéfico/maléfico); falsa comemoração; fase 1–8 |
| Regentes | regente das Casas 1, 4, 5, 7 e 10: casa, dignidade, velocidade, cazimi/combustão; ocupação mútua; cadeado fixo |
| Relações | aspectos (tipo, aplicando/separando, exato <1°); recepção mútua; antiscia; Nodo Norte/Sul; Mercúrio nos ângulos |
| Ângulos | signo/modalidade de ASC e MC; estrelas fixas (Algol, Regulus, Spica, Aldebaran, Antares); Casa 5 fértil/estéril |

Sinais de corpos lentos (signo/grau/dignidade de Júpiter a Plutão, Nodo, Lilith, Quíron) ficam fora
do motor por padrão, porque passam meses iguais. Isso pode ser mudado em Backup → Configuração.

## O motor Astral

O motor é uma **mistura bayesiana de modelos que aprendem online**, concurso a concurso, só com o passado:

- **Nulo** (todo número 60%) e **só frequência** (4 velocidades de aprendizado): a referência sem astrologia.
- **Contraste bayesiano** (4 variantes): para cada sinal ativo e cada número, compara a taxa *com* o sinal contra a
  taxa *sem* o sinal. A diferença recebe uma probabilidade de ser real (fator de Bayes beta-binomial). Sinais que só
  coincidem com um efeito verdadeiro ficam com contraste ~0, e isso resolve o problema de sinais correlacionados.
- **Regressão logística FTRL** (3 variantes, com L1): aprende pesos conjuntos, distribuindo o efeito entre sinais correlacionados.

Cada modelo pesa `exp(−perda logarítmica acumulada)`. Se os sinais não ajudam, a mistura vai sozinha para os
modelos sem astrologia, e a **confiança nos sinais** (peso dos modelos astrais) cai para perto de 0%.

Validação com dados sintéticos (`test/motor.test.js`):
- **acaso puro** → confiança nos sinais < 50%, média ≈ 9, permutação não acusa nada, 0 achados no FDR;
- **sinal plantado** (um sinal que empurra os números 1–5) → confiança 100%, permutação confirma (p < 0,05),
  e a descoberta põe o sinal plantado no topo com probabilidade de ser real > 90%.

## Como o sistema se protege de ilusões

| Risco | Proteção |
|---|---|
| Vazamento (usar o resultado para prever ele mesmo) | Tudo é cronológico; teste automático garante que trocar o resultado não muda a previsão |
| Muitos testes (35 mil no v12) | Probabilidade de ser real (spike-and-slab) + FDR; o painel mostra quantos p < 5% o acaso produziria |
| Sinais correlacionados somando o mesmo efeito | Contraste com/sem sinal + regressão conjunta + mistura que pune excesso de confiança |
| Achar padrão e testar no mesmo dado | Laboratório: hipótese congelada (data + hash), avaliada só em sorteios futuros, com SPRT |
| "Acertou 11" retroativo | Diário prospectivo: só conta jogo registrado antes do resultado existir |
| Acaso parecendo sinal | Teste de permutação: embaralha resultados entre dias e roda tudo de novo |

## Desenvolvimento

```bash
npm install
npm test          # parser, sinais, motor (acaso × sinal plantado), sem vazamento
npm run build     # gera dist/lotofacil-astro-v13.jsx
```

Desempenho medido com 321 mapas sintéticos (~186 sinais cada): leitura 0,3 s, simulação completa 1,6 s,
descoberta 0,3 s, cada permutação ~1,5 s.
